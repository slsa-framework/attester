# Build Type: Watcher (v1)

`buildType` URI: `https://slsa.dev/buildtypes/watcher/v1`

## Description

Provenance with this build type is generated by a *watcher*: an observer that
monitors a build system run from the outside, waits for it to complete and
attests its results. The watcher is not the build system itself — it records
what it observed about a run (and, for some subject sources, what the
platform or the build asserted about the artifacts), and its guarantees come
from where it ran and who signed the attestation, not from controlling the
build.

The reference implementation is
[slsa-attester](https://github.com/slsa-framework/attester)'s `watch`
subcommand observing GitHub Actions workflow runs. The field descriptions
below are written in GitHub Actions terms; other build systems may be
supported by future revisions.

A watcher attesting the run it is itself part of MUST run in a job dedicated
to attesting, with no other steps: anything that runs earlier in the job can
tamper with the watcher, and every step in the job shares the OIDC identity
the attestation is signed with. The reference implementation enforces this by
refusing to attest from a shared job.

## Build Definition

### External parameters

All external parameters are REQUIRED unless noted otherwise.

| Parameter | Type | Description |
| --- | --- | --- |
| `workflow` | string | Repository-relative path of the workflow that ran, e.g. `.github/workflows/release.yml`. |
| `repository` | string | HTTPS URI of the source repository, e.g. `https://github.com/slsa-framework/attester`. |
| `ref` | string | Fully-qualified git ref the run built, e.g. `refs/tags/v1.0.0`. When the ref is not known, the head commit sha. |
| `event` | string | Name of the event that triggered the run, e.g. `push` or `workflow_dispatch`. |
| `inputs` | object (OPTIONAL) | The workflow's inputs. When the watcher runs inside the attested run, these are the actual values from the triggering event's payload. Otherwise they are the defaults declared by the workflow definition at the run's commit, since the platform does not expose overridden values after the fact. Omitted when the workflow declares no inputs. |

### Internal parameters

Empty. Reserved for future revisions (e.g. runner environment details).

### Resolved dependencies

The first entry MUST describe the source repository at the commit the run
built:

```json
{
  "uri": "git+https://github.com/<owner>/<repo>@<ref>",
  "digest": { "gitCommit": "<sha>" }
}
```

Additional entries MAY record further dependencies the caller declared at
attestation time.

## Run details

### Builder

`runDetails.builder.id` identifies the workflow that ran, as
`https://github.com/<owner>/<repo>/<workflow path>@<ref>`.

The builder id is *claimed*, not proven: the watcher records the workflow it
observed. Verifiers MUST bind the claim to the attestation's signing identity
(see [Verification](#verification)).

### Metadata

| Field | Description |
| --- | --- |
| `invocationId` | URL of the run and attempt, e.g. `https://github.com/<owner>/<repo>/actions/runs/<id>/attempts/<n>`. |
| `startedOn` | Time the run started. |
| `finishedOn` | Time of the run's last update when the watcher collected it. |

## Subjects

The statement's subjects are the artifacts the run produced, gathered from
one or more sources with different trust properties:

| Source | Digest computed by |
| --- | --- |
| Workflow artifacts of the run | The watcher downloads and hashes them. |
| Release assets of a given tag | The platform (GitHub reports the digest it computed at upload); the watcher downloads and hashes assets the platform carries no digest for. |
| Top-level elements of an SBOM | Asserted by the SBOM; elements without hashes are rejected. |
| Checksum files (`sha256sum` format) and explicit `algorithm:digest` values | Asserted by the caller. |

## Verification

The provenance is only as trustworthy as its signer. Verifiers MUST:

- Verify the attestation's signature and pin the expected signing identity.
  When the provenance is generated through the
  [`slsa-framework/actions`](https://github.com/slsa-framework/actions)
  reusable workflow, the sigstore certificate identifies that workflow
  (`https://github.com/slsa-framework/actions/.github/workflows/attest_actions.yml@<ref>`)
  independently of the workflow being attested. When the attester action is
  called directly from a dedicated job, the certificate identifies the
  calling workflow, which must then be trusted directly.
- Check that `builder.id` names the expected workflow, and treat it as bound
  only through the signing identity above.
- Evaluate `externalParameters` against policy — in particular `repository`,
  `ref` and `inputs`, which are controlled by whoever triggered the run.

## Example

```json
{
  "buildDefinition": {
    "buildType": "https://slsa.dev/buildtypes/watcher/v1",
    "externalParameters": {
      "workflow": ".github/workflows/release.yml",
      "repository": "https://github.com/slsa-framework/attester",
      "ref": "refs/tags/v1.0.0",
      "event": "workflow_dispatch",
      "inputs": {
        "environment": "production",
        "skip-tests": false
      }
    },
    "resolvedDependencies": [
      {
        "uri": "git+https://github.com/slsa-framework/attester@refs/tags/v1.0.0",
        "digest": { "gitCommit": "0d0b358416b5ef26cca6f2fbf0e2c3c5db0d2be9" }
      }
    ]
  },
  "runDetails": {
    "builder": {
      "id": "https://github.com/slsa-framework/attester/.github/workflows/release.yml@refs/tags/v1.0.0"
    },
    "metadata": {
      "invocationId": "https://github.com/slsa-framework/attester/actions/runs/123456789/attempts/1",
      "startedOn": "2026-09-16T20:14:31Z",
      "finishedOn": "2026-09-16T20:19:02Z"
    }
  }
}
```
